# 公開前チェックリスト

Vercel で一般公開する前に確認すること。☐ をすべて確認してから公開してください。
法律・規約に関わる項目は、専門家（弁護士など）への確認を推奨します。このアプリの実装では判断できません。

## 1. 法務・ポリシー（公開前に必須）
- ☐ プライバシーポリシーを作成し、`/about` などから見られるようにした（収集する情報：メールアドレス、年代、任意のニックネーム、回答、診断結果、チーム内の表示名、操作の記録）
- ☐ 利用規約を作成した（診断は能力測定・選抜用ではないこと、年代・保護者の自己申告、チームでの利用ルール）
- ☐ 個人情報保護法、サービスを提供する地域の法令（未成年のデータ、保護者同意）を確認した
- ☐ 「FOOTBALL DNA」の名前の商標調査をした
- ☐ 実在のチーム・選手の名前、ロゴ、写真を使っていない

## 2. Supabase の設定
- ☐ SQL を3つとも実行済み（`20261102000001_phase2_core.sql`、`seed.sql`、`20261102000002_phase3_teams.sql`）
- ☐ Authentication → URL Configuration の Site URL を本番URLにし、Redirect URLs に `https://（本番URL）/auth/callback` を追加した
- ☐ Authentication → SMTP Settings で独自のメール送信を設定した（Supabase 標準のメール送信は1時間に数通まで。公開すると足りません）
- ☐ メールの文面（Authentication → Email Templates）を日本語にした（任意）
- ☐ service role key（secret key）をどこにも設定・公開していない
- ☐ Supabase の無料プランの制限（DB容量、1週間使わないと一時停止など）を確認した

## 3. Vercel の設定
- ☐ Environment Variables に `NEXT_PUBLIC_SUPABASE_URL`、`NEXT_PUBLIC_SUPABASE_ANON_KEY`、`NEXT_PUBLIC_SITE_URL`（本番URL、末尾スラッシュなし）を登録した
- ☐ 本番URLで HTTPS になっている
- ☐ 独自ドメインを使う場合は、Supabase と `NEXT_PUBLIC_SITE_URL` もそのドメインにした

## 4. 本番URLでの動作確認（スマホで）
- ☐ ゲストで診断 → 結果 → SNS画像のダウンロード
- ☐ ログイン（メールのリンク）→ 結果をアカウントに保存 → 履歴に出る
- ☐ 共有リンク：作成 → 公開 → 別の端末で見られる → 失効 → 見られない
- ☐ 共有リンクを LINE / X に貼ったとき、画像付きで表示される（OGP）
- ☐ チーム：作成 → 招待コード → 別アカウントで参加申請 → 承認 → 選手が「見せる」→ コーチに表示 → やめる → 非表示
- ☐ 18歳未満の選手：保護者確認リンク → 保護者が承認 → 保護者がチーム共有に同意 → コーチに表示
- ☐ ホーム画面に追加（iPhone: 共有ボタン →「ホーム画面に追加」、Android: メニュー →「アプリをインストール」）でアイコンが出る
- ☐ 機内モードにして、トップと診断の途中が開ける／マイページはオフライン画面になる
- ☐ アカウント削除で、保存した結果・共有リンク・チーム（オーナーの場合）が消える

## 5. 権限・漏洩テスト
- ☐ `npm run test:db`（他人の結果が見えない、無同意の選手がコーチに見えない、招待の期限切れ・取り消し、など）が通る ※GitHub の CI で毎回実行
- ☐ ログインしていない状態で `/me`、`/teams`、`/settings` を開くとログイン画面になる
- ☐ 他人の結果のURL（`/results/…`）を開いても見えない
- ☐ チームに入っていない人が `/teams/（チームID）` を開いても見えない

## 6. 運用
- ☐ エラーの通知先を決めた（Vercel のログ、必要なら Sentry など）
- ☐ 問い合わせ先（メールアドレスやフォーム）を用意した
- ☐ データ削除の依頼があったときの手順を決めた（本人は設定画面から削除可能）
- ☐ `npm audit` の警告を確認した（`npm audit fix --force` は使わない）

## 7. 食事ガイド
- ☐ `/nutrition` を自分のスマホで開き、年代・タイプ・活動状況・キックオフ時間を切り替えて表示が崩れない
- ☐ 献立の内容（料理名・目安量・作り方・代替）を自分の目で読んで、違和感がない
- ☐ 出典のリンクが開ける
- ☐ `src/data/note-links.json` の `membershipUrl` に note のメンバーシップのURLを入れた（入れるまでボタンは「準備中」表示）

## 既知の制限（公開前に理解しておくこと）
- 年代・保護者は自己申告です。未成年が年代を偽ったり、保護者でない人が保護者を名乗ることは技術的に防げません。
- レート制限はサーバーのメモリ上で行っているため、Vercel では効果が限定的です。利用者が増えたら共有ストア（Upstash など）に置き換えます。
- 英語版は文言の仕組みだけ用意しています（設問・タイプ説明は日本語のみ）。
- 食事ガイドは医師・管理栄養士の監修を受けていません。献立は JFA 栄養ガイドラインなどの公開資料をもとに運営が作成したものです。アレルギーの絞り込みは主な8品目だけで、調味料・市販品の原材料や調理中の混入までは確認できません。
- 管理者用の設問管理画面（`/admin/questions`）はありません。設問は `src/data/` の JSON と `supabase/seed.sql` で管理します。
